# Архитектура системы Airi

Данный документ описывает внутреннее устройство backend-сервера, подсистем и цикла обработки запросов.

---

## 1. Общий жизненный цикл запроса

```text
[ Пользователь вводит запрос в HUD ]
                  │
                  ▼
         POST /api/query/stream (SSE)
                  │
                  ├── 1. Проверка блокировки контрольной суммы (Critical Checksum)
                  │      Если сумма отличается от сигнатуры обучения и блокировка активна -> Ошибка
                  │
                  ├── 2. Инференс FunctionGemma (Local Endpoint / Built-in Engine)
                  │      Определение целевого инструмента и аргументов
                  │
                  ├── 3. Событие SSE: tool_invoked
                  │      HUD показывает бейдж вызванного инструмента и анимацию ожидания
                  │
                  ├── 4. Исполнение инструмента в ModulesRegistry
                  │      Внедрение контекста: config, storage, views
                  │
                  └── 5. Событие SSE: completed
                         Возврат результата, данных логирования и объекта ViewSpec для отображения
```

---

## 2. Подсистемы Backend

### 2.1 ModulesRegistry (`server/modulesRegistry.ts`)
- Сканирует директорию `/modules/*` при старте и по запросу `POST /api/modules/reload`.
- Для каждой папки считывает:
  - `module.json` — метаданные (название, версия, автор, массив инструментов).
  - `config.ini` — параметры настройки модуля в формате INI.
  - `.js` файлы логики инструментов.
- Вычисляет каноническую контрольную сумму (SHA-256) всех активных сигнатур инструментов.
- Предоставляет безопасную среду выполнения инструментов через `new Function(...)` с изолированным контекстом `context`.

### 2.2 FunctionGemmaService (`server/functionGemmaService.ts`)
- Преобразует активный список инструментов в системный промпт формата Gemma `<start_of_turn>`.
- Поддерживает подключение к локальному эндпоинту FunctionGemma (Ollama / vLLM / TextGen).
- Содержит встроенный движок сопоставления интентов и шаблонов для мгновенной автономной работы.

### 2.3 StorageService (`server/storageService.ts`)
- Обеспечивает изолированное хранилище в папке `/storage/` на диске.
- Позволяет инструментам читать, писать и удалять файлы пользовательских данных (заметки, кэш, история).
- Предоставляет API для изменения пути хранилища из настроек.

### 2.4 LoggerService (`server/loggerService.ts`)
- Фиксирует каждый выполненный запрос, имя модели, длительность в миллисекундах и результат.
- Позволяет оценивать точность модели (`EXACT`, `HALLUCINATED`, `WRONG_TOOL`, `FAILED`).
- Позволяет экспортировать датасет обучения в форматах JSON и JSONL.
